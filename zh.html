Task Router — 用一个 Markdown 文件调度 Agent

AI 内容工作流

2026 年 4 月搭建 · 一个 Agent、八个 Skill、一份共享的方法论文件

给自己拍短视频搭的一套工作流：一个 Agent，八个 Skill，分别负责筛选题、写脚本、改开头、起标题、检查 AI 腔、找对标和数据复盘。每条视频发出后，复盘 Skill 会把数据得出的结论写回一份共享的方法论文件，下次选题时直接读取。

结果：这份方法论文件已经根据数据淘汰了 4 类我以前常做的内容，靠数据说话，不靠感觉。

产品设计 · 交互原型 2026

Rooted（根）— 用交互讲清汉字的来龙去脉

可在线体验 · 每个版本只验证一个假设

从 0 到 1 独立完成设计和上线，做了两个版本，每个版本只验证一个产品假设。V1 把“马”字三千年的字形演变压缩进一次滑动，看交互本身能不能代替说明文字，让学习者自己看明白；V2 把“妈”拆成“女 + 马（表音）”，看把字的结构画出来，能不能降低记忆负担。

产品思路：让交互本身把价值讲清楚。如果用户滑一下就能自己想通这个字是怎么来的，设计就成立了。下一步是做正式的用户测试，和死记硬背比较记忆保持率，再决定 V3 怎么做。

Mini Agent Harness — 一个小型 Harness 和检验它的回归集

GitHub 公开仓库 · 只用 Python 标准库 · 14 个回归用例

一个小型 Agent Harness：带步数上限的循环、两个工具、每一步都有轨迹记录，并且 Agent 只能提出文件修改，必须由人确认后才会写入。回归集覆盖正常运行、工具报错、安全、模型出错、停止和人工确认六类情况。

检验检查本身：我故意拆掉路径防护和覆盖检查，看回归集能不能发现。结果有一个用例照样通过了，因为它要读的文件本来就不存在。我把这个用例改成先在工作区外放一个真实文件。

技术 Demo · 开源 2026

Function Calling Demo — 不用框架，手写一个 tool-use 循环

GitHub 公开仓库 · 约 350 行 Python · 13 个 pytest 测试（含安全边界测试）

不依赖任何框架，直接调用 Anthropic API 写的 tool-use Agent：5 个带 JSON Schema 的类型化工具、一个分发器、在 handler 层强制执行的路径穿越防护，以及带注释的 MAX_TOOL_ITERATIONS 迭代上限。目的是弄懂底层原理，而不是学会某个框架。

为什么做这个：LangChain、AutoGen、Claude Agent SDK 这些框架，底下包的都是同一个循环。把它写到最简，很多设计取舍反而一目了然：为什么多个类型化工具比一个万能工具好，为什么安全边界要写在代码里而不是 prompt 里，以及为什么频繁触发迭代上限，往往说明工具设计或任务拆分有问题。

Research · Modelling 2025

南非电力需求预测与调度优化

德勤导师指导的案例 · 巴黎大学小组项目

为南非电力系统做的一套完整量化分析：横向比较 6 种预测模型（从传统的 ARIMA 到深度学习的 TFT），再用 Pyomo 在碳排放、装机容量和合同约束下做调度优化，目标是让系统总成本最低。

主要发现：在尾部风险指标上，简单的计量模型 SARIMAX 反而胜过 LSTM 和 TFT。供给结构性紧张时，越简单的模型越稳。

研究 · NLP 2025

欧洲劳动力市场机器人暴露指数

巴黎一大「发展大数据」课程 · 小组研究

下载海报

用专利文本和职位描述语料，通过 LSA（潜在语义分析）为欧洲各职业构建了“机器人暴露指数”。结果显示，中等收入、以常规任务为主的职业受自动化冲击最大，与劳动力市场极化理论一致。

核心结果：在 34 个欧洲国家的样本中，机器人暴露度每高一个标准差，职业平均时薪低约 7.2%（β = −0.072，p < 0.001）。这是相关关系，不代表因果。
